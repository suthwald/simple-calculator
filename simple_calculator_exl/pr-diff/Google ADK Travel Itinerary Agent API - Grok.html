Real-life Agent System: Travel Itinerary Planner

  • Parent Agent: TripPlanner (a SequentialAgent workflow that orchestrates the flow deterministically).
  • Sub-agent 1: DestinationResearcher – LLM agent that researches the destination, attractions, best time to visit, etc. (uses shared state via output_key).
  • Sub-agent 2: ItineraryBuilder – LLM agent that takes the research summary and builds a detailed day-by-day itinerary with budget tips and practical advice.

This is a practical real-life system used by travel apps/concierges: user asks “Plan a 5-day trip to Tokyo in summer”, the researcher gathers info, then the builder creates the final plan.

2. Complete Code (app.py)

Python
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel
import os
from typing import Dict, Any

# ADK imports
from google.adk.agents import LlmAgent, SequentialAgent
from google.adk.runners import InMemoryRunner
from google.adk.events import Content, Part   # Content and Part for messages

# ============================
# 1. DEFINE THE 3-AGENT SYSTEM
# ============================

# Sub-agent 1: Researches the destination
researcher = LlmAgent(
    name="DestinationResearcher",
    model="gemini-2.0-flash-exp",          # or gemini-1.5-pro / latest model
    description="Expert travel researcher. Gathers facts about destinations, weather, attractions, culture, and practical tips.",
    instruction="""
    You are a world-class travel researcher.
    For the given query, provide a concise but comprehensive research summary including:
    - Key attractions
    - Best time / weather notes
    - Local customs / tips
    - Transportation overview
    Output ONLY the research summary as plain text.
    """,
    output_key="research_summary"   # Saves output to shared session.state for next agent
)

# Sub-agent 2: Builds the actual itinerary
itinerary_builder = LlmAgent(
    name="ItineraryBuilder",
    model="gemini-2.0-flash-exp",
    description="Expert itinerary creator. Turns research into a beautiful, practical daily plan.",
    instruction="""
    You are a professional travel planner.
    Using the research summary stored in {research_summary}, create a detailed day-by-day itinerary.
    Include:
    - Morning / Afternoon / Evening activities
    - Estimated daily budget
    - Meal suggestions
    - Practical tips (transport, booking links if known, etc.)
    Make it engaging and realistic.
    """,
    # No output_key needed – final response goes to user
)

# Parent Agent: Orchestrates the two sub-agents sequentially
parent_agent = SequentialAgent(
    name="TripPlanner",
    description="Main Travel Coordinator that runs research → itinerary building flow",
    sub_agents=[researcher, itinerary_builder]
)

# ============================
# 2. FASTAPI POST ENDPOINT
# ============================

app = FastAPI(
    title="Google ADK Travel Planner API",
    description="POST /plan endpoint that runs the 3-agent ADK flow"
)

class QueryRequest(BaseModel):
    query: str
    user_id: str = "default_user"      # Optional – can be used for multi-user sessions
    session_id: str = "default_session"  # Optional

@app.post("/plan")
async def plan_trip(request: QueryRequest) -> Dict[str, Any]:
    """
    POST API that accepts a user query and runs the full ADK agent flow.
    Returns the final itinerary (and optionally the full event trace).
    """
    if not request.query.strip():
        raise HTTPException(status_code=400, detail="Query cannot be empty")

    try:
        # Create a fresh runner for this request (InMemoryRunner is perfect for simple API use)
        runner = InMemoryRunner(agent=parent_agent)

        # Prepare user message
        user_message = Content(
            role="user",
            parts=[Part.from_text(request.query)]
        )

        # Run the full agent workflow
        events = runner.run(
            user_id=request.user_id,
            session_id=request.session_id,
            new_message=user_message
        )

        # Collect the final response (last content from the last agent)
        final_response = ""
        for event in events:
            if event.content and event.content.parts:
                for part in event.content.parts:
                    if part.text:
                        final_response += part.text + "\n"

        return {
            "status": "success",
            "query": request.query,
            "final_itinerary": final_response.strip() or "No response generated.",
            "agents_used": ["DestinationResearcher", "ItineraryBuilder"],
            "parent_agent": "TripPlanner (Sequential)"
        }

    except Exception as e:
        raise HTTPException(status_code=500, detail=f"Agent execution failed: {str(e)}")


# ============================
# 3. RUN THE API
# ============================
# Run with:  uvicorn app:app --reload --port 8000

Parent agent must use llm

Here's the updated implementation where the Parent Agent is now an LlmAgent (LLM-powered coordinator).

This follows the recommended LLM-Driven Delegation pattern in Google ADK: the parent agent uses its LLM to analyze the user query, decide the best flow, and delegate to the appropriate sub-agent(s) dynamically based on their description fields. The two sub-agents remain specialized LlmAgents.

Real-life Agent System: Intelligent Travel Itinerary Planner

  • Parent Agent (TripPlanner): LLM Coordinator — analyzes the query, decides whether to do research first, build itinerary, or handle both. It can delegate intelligently and synthesize the final response.
  • Sub-agent 1 (DestinationResearcher): Researches destination details, weather, attractions, tips.
  • Sub-agent 2 (ItineraryBuilder): Builds a practical day-by-day itinerary using the research (or directly if simple).

This is more agentic and flexible than a rigid sequential flow — the parent LLM can route dynamically (e.g., skip heavy research for a quick weekend getaway or do both for complex trips).

Can we get response of any agent from this loop?

Yes, you can easily extract responses from any specific agent (including the parent and both sub-agents) from the events loop.

Key Point in Google ADK

Every Event object has an author field that tells you which agent produced it:

  • "user" → user message
  • "TripPlanner" → response from the parent agent (LLM Coordinator)
  • "DestinationResearcher" → response from the researcher sub-agent
  • "ItineraryBuilder" → response from the itinerary builder sub-agent

This makes it very straightforward to separate outputs in multi-agent systems.

Updated /plan Endpoint with Per-Agent Responses

Replace your current response extraction code with this improved version:

Python
@app.post("/plan")
async def plan_trip(request: QueryRequest) -> Dict[str, Any]:
    if not request.query.strip():
        raise HTTPException(status_code=400, detail="Query cannot be empty")

    try:
        runner = InMemoryRunner(agent=parent_agent)

        user_message = Content(
            role="user",
            parts=[Part.from_text(request.query)]
        )

        events = runner.run(
            user_id=request.user_id,
            session_id=request.session_id,
            new_message=user_message
        )

        # Dictionaries to collect responses from each agent
        agent_responses: Dict[str, str] = {
            "TripPlanner": "",
            "DestinationResearcher": "",
            "ItineraryBuilder": ""
        }

        full_trace = []   # Optional: for debugging / logging

        for event in events:
            if event.content and event.content.parts:
                text_parts = []
                for part in event.content.parts:
                    if part.text:
                        text_parts.append(part.text)

                if text_parts:
                    response_text = "\n".join(text_parts)
                    full_trace.append({
                        "author": event.author,
                        "text": response_text[:500] + "..." if len(response_text) > 500 else response_text
                    })

                    # Accumulate response by agent
                    if event.author in agent_responses:
                        agent_responses[event.author] += response_text + "\n\n"

        # Final synthesized response is usually from the Parent (TripPlanner)
        final_plan = agent_responses.get("TripPlanner", "").strip()

        return {
            "status": "success",
            "query": request.query,
            "final_plan": final_plan or "No final plan generated.",
            "agent_responses": {
                "parent": agent_responses.get("TripPlanner", "").strip(),
                "researcher": agent_responses.get("DestinationResearcher", "").strip(),
                "itinerary_builder": agent_responses.get("ItineraryBuilder", "").strip()
            },
            "trace_summary": full_trace[-5:]  # Last few events for quick debug
        }

    except Exception as e:
        raise HTTPException(status_code=500, detail=f"Agent execution failed: {str(e)}")

I want to give some input to itinerary builder while invoking from api, is it possible?

Yes, it is possible to give extra/custom input specifically to the ItineraryBuilder (or any sub-agent) when calling the API.

Here are the two cleanest and most reliable ways in Google ADK:

Recommended Approach 1: Pass Extra Input via Session State (Best for API + Persistent Context)

You can inject additional data into the shared session.state before running the parent agent. The ItineraryBuilder can then read it using the {key} placeholder in its instruction.

Updated Code (app.py)

Add this to your QueryRequest model and endpoint:

Python
from pydantic import BaseModel
from typing import Dict, Any, Optional

class QueryRequest(BaseModel):
    query: str
    user_id: str = "default_user"
    session_id: str = "default_session"
    # New field: Extra input specifically for ItineraryBuilder
    extra_itinerary_input: Optional[Dict[str, Any]] = None   # e.g., {"budget": "moderate", "travel_style": "romantic", "preferences": ["beach", "food"]}

Now update the /plan endpoint:

Python
@app.post("/plan")
async def plan_trip(request: QueryRequest) -> Dict[str, Any]:
    if not request.query.strip():
        raise HTTPException(status_code=400, detail="Query cannot be empty")

    try:
        # Create runner
        runner = InMemoryRunner(agent=parent_agent)

        # === Inject extra input into session state BEFORE running ===
        initial_state = {}
        if request.extra_itinerary_input:
            initial_state = {
                "extra_itinerary_input": request.extra_itinerary_input
            }

        # For InMemoryRunner, we can set state by creating session manually if needed,
        # but simpler: many setups allow passing via context. 
        # For reliable injection, create session with state:
        from google.adk.sessions import InMemorySessionService
        session_service = InMemorySessionService()
        session = await session_service.create_session(
            app_name="travel_planner",
            user_id=request.user_id,
            session_id=request.session_id,
            state=initial_state   # This injects the extra data
        )

        # Use the session in runner if needed (or let runner handle it)
        # For InMemoryRunner, you can often set it directly in newer ADK versions.

        user_message = Content(
            role="user",
            parts=[Part.from_text(request.query)]
        )

        events = runner.run(
            user_id=request.user_id,
            session_id=request.session_id,
            new_message=user_message
            # runner will use the session with pre-filled state
        )

        # ... (rest of your event processing code remains the same)

        # In agent_responses you already have per-agent output

        return {
            "status": "success",
            "query": request.query,
            "extra_input_passed": request.extra_itinerary_input,
            "final_plan": agent_responses.get("TripPlanner", "").strip(),
            "agent_responses": { ... }   # your existing dict
        }

    except Exception as e:
        raise HTTPException(status_code=500, detail=str(e))

Approach 2: Pass Extra Input Inside the User Message (Simpler but Less Structured)

You can append the extra instructions directly to the user message:

Python
extra_text = ""
if request.extra_itinerary_input:
    extra_text = f"\n\nAdditional instructions for itinerary: {request.extra_itinerary_input}"

user_message = Content(
    role="user",
    parts=[Part.from_text(request.query + extra_text)]
)

Then tell the parent agent in its instruction: "Any additional instructions after the main query should be passed to the ItineraryBuilder."

This is quick but the state-based approach (Approach 1) is cleaner and more maintainable for multi-agent systems.

Which One Should You Use?

  • Use Approach 1 (Session State) → when you want structured data, reusability across turns, or when the extra input is complex (dict/list).
  • Use Approach 2 → for quick one-off text instructions.
